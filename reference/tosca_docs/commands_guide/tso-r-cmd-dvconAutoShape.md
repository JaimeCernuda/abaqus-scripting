# DVCON_AUTO_SHAPE

| |  |  | | --- | --- | | DVCON\_AUTO\_SHAPE | | |  | | | |  | | --- | | Automatic generation of design variable constraints (`DVCON_SHAPE` commands) with link conditions (`LINK_SHAPE` command) for shape optimization.  This page discusses:   * Remarks * Examples | | |   |  |  |  | | --- | --- | --- | | ID\_NAME | = `<id_family_name_dvcon_shape>`\* | Name of the `DVCON_AUTO_SHAPE` definition. This `ID_NAME` is also used as family name for the `DVCON_SHAPE` definitions. | | ND\_GROUP\_FAMILY | = <nd\_group\_family\_name>\* | Family name of the node groups which are selected for the coupling using the definitions. | | CHECK\_LINK | = <link\_shape\_name> | Name of the `LINK_SHAPE` definition. |   Remarks  1. The operators `ID_NAME` and `ND_GROUP_FAMILY` are given the symbol \* to identify the use of a family name in the command.    The symbol represents any string of symbols and must be entered for both operators. Each node group with the given family name receives a design variable    constraint with the present family name. The string of symbols \* given to the node group (supplementary to the full name of the node group) is defined and    listed as having the identical string of characters \* to the `ID_NAME` of the generated `DVCON_SHAPE`. 2. This command can be used quite well in combination with `GROUP_AUTO_DEF` because the child groups begin with the same prefix.    While referencing the group names in `DVCON_AUTO_SHAPE`, the underline \_ after the family name is very important because otherwise    the `DVCON_SHAPE` entry is also set for the parent group. This can lead to unwanted side effects.  Examples  ``` DVCON_AUTO_SHAPE   ID_NAME         = my_dvcon_*   ND_GROUP_FAMILY = ND_SIDE_A_*   CHECK_LINK      = my_link_shape_01 END_ ``` |
