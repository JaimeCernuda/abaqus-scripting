The following four points of the optimization process are known to be the most frequent in which an error might occur:   1. Stop at the start of the program (configuration, licensing, and tosca\_driver start). 2. Stop in a preprocessing step (`FEM_INCLUDE, FEM_TO_ONF, TOSCA_PREP`). 3. Stop during a FE analysis. 4. Stop in an optimization step (`RES_TO_VTM, TOSCA_OPT, FEM_MODIF`).   For a more detailed description of the program sequence, see the figure in Program Sequence and Data Flow of Tosca Structure. When the program is started, the configuration is first loaded and the licenses are checked. Information regarding this can be found in the protocol file authorization.log (see also Special Logfiles).  Afterwards, tosca\_driver is started. Protocol information is printed to the display and to the file `TOSCA.OUT`. The sequence of configuration files that are read in the beginning of the optimization is logged to `TOSCA.OUT`:    For each module that is started by tosca\_driver and finishes, an entry with information concerning the launch of the module can be found.
