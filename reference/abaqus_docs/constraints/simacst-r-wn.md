| |  |  | | --- | --- | | What's New | | |  | | | |  | | --- | | This page describes recent changes in Abaqus Constraints.   * [2024 FD01](#simacst-r-wn__rs-R2024x-FD01) | | |   2024 FD01 Conversion of Select Distributed Couplings to Tie Constraints Abaqus/Explicit now converts distributing couplings to a tie constraint by default when the distributing couplings have cloud nodes associated with a single element facet and when the reference node of the coupling is not a node of a connector element.  Benefits: This enhancement avoids the creation of overlapping distributed couplings (which introduce a small amount of artificial mass for numerical purposes) when modeling fasteners using solid elements.  Some workflows involve fastening two surfaces together with the stiffness of the connection represented by a hexahedral element instead of a connector element, as shown in [Figure 1](#simacst-r-wn__fig_i4s_rp5_jzb). Each node of the hexahedral element acts as a reference node of a distributing coupling whose cloud nodes are associated with a single shell element, as shown in [Figure 2](#simacst-r-wn__fig_ncz_fq5_jzb). This approach results in some shell nodes participating in two or four distributing couplings. Abaqus/Explicit generally introduces artificial mass to nodes acting as clouds nodes in multiple distributing couplings. By changing the default behavior for automatic conversion of distributing couplings to tie constraints, Abaqus/Explicit reduces the likelihood of adding artificial mass to a model. Figure 1. A fastener construct involving a hexahedral element representing the faster stiffness.    Figure 2. Highlighted connectivity for one of eight user-defined distributing couplings associated with a fastener connection.     Constraint coefficients are somewhat different for distributed couplings than they are for tie constraints in such cases. [Figure 3](#simacst-r-wn__fig_kps_fr5_jzb) provides perspective on these differences. A downward unit force is applied at node 101. Node 101 is connected to a single square face with a distributed coupling for the case on the left versus a tie constraint for the case on the right. The four nodes of the square face are fixed with boundary conditions. Node 101 corresponds to the position one-tenth along the diagonal line from nodes 1 to 4. The vertical reaction forces (RF3) for nodes 1 through 4 are 0.65, 0.25, 0.25, and -0.15 for the distributing coupling case; and for the tie constraint case these reaction forces are 0.81, 0.09, 0.09, and 0.01, respectively. These sets of reaction forces are statically equivalent (both sets of reaction forces sum to 1.0 and do not generate a moment about the location of node 101). Because the constraint coefficients are different in the two approaches, some differences in the local behavior around the constraint are expected due to this conversion. Figure 3. Comparison of reaction forces for a distributed coupling versus a tie constraint acting between node 101 and a single quad face, with unit downward load applied at node 101 and boundary conditions acting at nodes 1 through 4.     You can override this conversion from distributed couplings to tie constraints if desired.  The recommended technique for modeling compliant fasteners is to use connector elements instead of hexahedral “nuggets.” This enables the use of larger numbers of cloud nodes per coupling, which reduces mesh sensitivity without having nodes act as cloud nodes in multiple overlapping distributed couplings.
