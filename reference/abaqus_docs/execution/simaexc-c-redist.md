| |  |  | | --- | --- | | Reducing Analysis Database File Sizes for Restart | | |  | | | |  | | --- | | The abaqus redistadb utility efficiently extracts a single frame of restart data from existing analysis database files. The analysis database for an Abaqus/Standard analysis consists of state (.stt) and model (.mdl) files and is required for continuation workflows such as restart, import, map solution, and symmetric results transfer. For analyses that have multiple restart frames, these files can get large in size. You can use this utility to create analysis database files (.stt and .mdl files) that contain only a selected restart frame. You can use these files to run continuation workflows.  The existing analysis database files can be in global form (.stt and .mdl) or domain form (stt.0, stt.1, etc. and mdl.0, mdl.1, etc.). In the case where domain-specific files are used, this utility creates analysis database files pertaining to the specified restart frame in global form (.stt and .mdl). This name must be different from the oldjob name that you specify. If it is omitted, a default name is derived by adding the suffix \_RES to the oldjob name.  input  This option is used to provide the name of an Abaqus input file that contains [RESTART](.._SIMACAEKEYRefMap_simakey-r-restart.md#simakey-r-restart), READ or [IMPORT](.._SIMACAEKEYRefMap_simakey-r-import.md#simakey-r-import) so that the step and increment specified by either of these options can be extracted and used to generate the reduced analysis database.  step  This option is used to specify the step in the existing analysis database from which a frame will be extracted. In combination with the increment option, it allows you to specify an exact frame for extraction. It provides an alternate and direct method of reducing the analysis database that does not require an input file. Hence, this option is applicable only if the input option is omitted.  If the step option is specified but the increment option is omitted, the last saved increment of the specified step is extracted.  increment  This option is used to specify an increment number in the existing analysis database that will be extracted. In combination with the step option, it allows you to specify an exact frame for extraction. It provides an alternate and direct method of reducing the analysis database that does not require an input file. Hence, this option is applicable only if the input option is omitted.  outdir  This option is used to specify the directory where the previous analysis database files reside and the reduced analysis database files are to be created. The default directory is the working directory.  copyfiles  This option is used to make a copy of the .odb, .prt, .res, .sim, and .fil (if it exists) files under the newjob-name or the derived name oldjob-name\_RES from the previous analysis so that a subsequent analysis can run with the reduced analysis database.  You can use an alternate syntax of -copyfiles without the value.  list  This option is used to list all the saved frames (step and increment) within the existing analysis database from a previous analysis.  You can use an alternate syntax of -list without the value.  help  This option prints a summary of the abaqus redistadb command syntax.  You can use an alternate syntax of -help without the value.  Examples You can run the stand-alone analysis database redistributor as follows:  ``` abaqus redistadb oldjob=test_old input=contactdamp_restart copyfiles=yes ```  This command generates the reduced Abaqus analysis database files (.mdl and .stt) under a default name with the persistent data extracted from the previous analysis database at the frame specified by [RESTART](.._SIMACAEKEYRefMap_simakey-r-restart.md#simakey-r-restart), READ in the given input file. The command also copies the .odb, .prt, .res, .sim, and .fil (if it exists) files from the previous analysis.  You can then run the subsequent analysis with the reduced analysis database using the following command:  ``` abaqus job=test_res input=contactdamp_restart oldjob=test_old_RES cpus=4 threads_per_mpi_process=2 ``` |
