# Excluding part instances from an analysis

| |  |  | | --- | --- | | Excluding part instances from an analysis | | |  | | | |  | | --- | | You can exclude part instances from the analysis so that they are not written to the input file when the analysis job is submitted. An excluded part instance participates in all operations other than the analysis. | | |  | | --- | | See Also | | [Using the Model Tree to manipulate part instances](simacae-c-asmmodeltree.md) | |   In the Model Tree, select the part instances that you want to exclude from the analysis. Click mouse button 3, and select Exclude from Simulation. Similarly, you can include part instances that were previously excluded by selecting Include in Simulation. Constraints on the part instances are retained if you exclude the instances from the analysis and subsequently include them.  By default, part instances that are excluded from the analysis are colored dark gray in the viewport. Icons are displayed in the Model Tree to indicate the excluded status of part instances and to indicate the linked and excluded status of part instances if the part instances are also linked between models, as shown in [Figure 1](simacae-c-asmconcinstanceslinking.md#simacae-c-asmconcinstanceslinking__simacae-iconslinking). `Contact-1` and `Contact-2` are part instances that are excluded from the analysis, and `Beam-2` is a linked and excluded part instance. For more information, see [Linking part instances between models](simacae-c-asmconcinstanceslinking.md). |
