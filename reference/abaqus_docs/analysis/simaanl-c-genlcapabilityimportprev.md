Abaqus/Standard Abaqus/Explicit    Introduction to Importing External Fields You can import external fields from an output database (.sim) file, also referred to as a SIM database (see [The Output Database](.._SIMACAEOUTRefMap_simaout-c-output.md#simaout-c-output-formats)), or from another output database for which a Reader process is available. Once imported, the external field can be used to define distributions, initial conditions, and history-dependent fields (such as loads, boundary conditions, and predefined fields). External fields can also be used for node-based submodeling as discussed in [About Submodeling](simaanl-c-submodeloverview.md).  The external field can be evaluated at nodes, integration points, or element centers. Conservative mapping is performed automatically if the fields are evaluated at different locations or if the meshes are different. Importing an external field is supported for most two-dimensional and three-dimensional continuum elements. When used to define distributions and initial conditions, external fields are also supported for three-dimensional conventional shell elements made of a single material. All field quantities are exchanged in the global Cartesian coordinate system.  Abaqus offers alternate interfaces for sequential coupling (see [Predefined Fields for Sequential Coupling](simaanl-c-sequentiallycoupledfields.md), [Sequentially Coupled Thermal-Stress Analysis](simaanl-c-thermstressanal.md), and [Predefined Loads for Sequential Coupling](simaanl-c-sequentiallycoupledloads.md)). These interfaces are limited to importing temperatures, normalized concentrations, and electromagnetic loads of a previous Abaqus analysis.  Specifying the Output Database File to Be Read External fields can be read from various supported output databases. A reader process, an executable designed to read a particular database format, is started by the Abaqus driver to read and transfer the field data. By default, the SIM database (.sim file) reader is used.  You can import external fields from a SIM database (.sim) file. You specify the file name (including the file extension) from which to import external fields.  You can import history-dependent fields from a supported non-SIM database. You must specify the reader executable name and database file name. Consult the respective solver manual to install and determine the reader executable name.  Input File Usage  Use the following option to specify a SIM database:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name.sim ```   Use the following option to specify a non-SIM database file name and reader executable name:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), READER=reader executable name, FILE=file name ```  Importing an External Field to Define Distributions You can import external fields to define distributions (see [Defining Distributions by Importing Field Data from an Output Database File](.._SIMACAEMODRefMap_simamod-c-definingdistributions.md#simamod-c-definingdistributions-t-usingoutputdatabase)). A common case is an injection molding manufacturing process where a molten fibrous material is injected into a mold. You can use injection molding software to model the manufacturing process and then import the section and material properties (such as local element orientation and fiber dispersion) into a subsequent stress-displacement simulation.  Input File Usage  Use the following options to import an external field to define a distribution:   ``` [DISTRIBUTION](.._SIMACAEKEYRefMap_simakey-r-distribution.md#simakey-r-distribution), TABLE=distribution table name  , field data [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name [DISTRIBUTION TABLE](.._SIMACAEKEYRefMap_simakey-r-distributiontable.md#simakey-r-distributiontable), NAME=distribution table name ```  Importing an External Field to Adjust Nodal Coordinates You can import an external field to adjust nodal coordinates.  One common case is to introduce a geometric imperfection into a model for a postbuckling analysis. In this case, the previous analysis must contain the mode shapes from an eigenfrequency extraction analysis or nodal displacements from a static or dynamic analysis. Mapping is performed if the postbuckling analysis uses a dissimilar mesh. The imperfection is introduced by adjusting the nodal coordinates using the imported modal shapes or nodal displacements.  Another common case is to adjust nodal coordinates using the deformed configuration from a previous analysis. In this case, the previous analysis must write the nodal displacements to a SIM database.  Input File Usage  Use the following options to import mode shapes to introduce a geometric imperfection:   ``` [ADJUST](.._SIMACAEKEYRefMap_simakey-r-adjust.md#simakey-r-adjust), NODE SET=nset, DISTRIBUTION=distribution name [DISTRIBUTION](.._SIMACAEKEYRefMap_simakey-r-distribution.md#simakey-r-distribution), NAME=distribution name, TABLE=distribution table name  , field data [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name, MODE=mode number [DISTRIBUTION TABLE](.._SIMACAEKEYRefMap_simakey-r-distributiontable.md#simakey-r-distributiontable), NAME=distribution table name ```   Use the following options to import nodal displacements to adjust nodal coordinates:   ``` [ADJUST](.._SIMACAEKEYRefMap_simakey-r-adjust.md#simakey-r-adjust), NODE SET=nset, DISTRIBUTION=distribution name [DISTRIBUTION](.._SIMACAEKEYRefMap_simakey-r-distribution.md#simakey-r-distribution), NAME=distribution name, TABLE=distribution table name  , field data [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name [DISTRIBUTION TABLE](.._SIMACAEKEYRefMap_simakey-r-distributiontable.md#simakey-r-distributiontable), NAME=distribution table name ```  Importing an External Field to Define Initial Conditions You can import an external field to define initial conditions (see [Initial Conditions](.._SIMACAEPRCRefMap_simaprc-c-initialcond.md)). A common case is a geomechanics analysis where you import an initial pore pressure field. You can compute a pore pressure field using a reservoir code and then import the field into a subsequent geostatic stress state procedure (see [Geostatic Stress State](simaanl-c-geostatstress.md)). This procedure is used to compute the equilibrium state before performing a geotechnical analysis using the coupled pore fluid diffusion and stress analysis procedure in Abaqus (see [Coupled Pore Fluid Diffusion and Stress Analysis](simaanl-c-coupdiffstress.md)). In this case, the reservoir code must write the pore pressure to a SIM database.  Input File Usage  Use the following options to import an external field to define initial conditions:   ``` [INITIAL CONDITIONS](.._SIMACAEKEYRefMap_simakey-r-initialconditions.md#simakey-r-initialconditions) [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name ```  Importing an External Field to Define History-Dependent Fields You can import external fields to define loads, boundary conditions, and predefined fields. A common case is a sequential thermal-stress analysis, where you first perform a heat transfer analysis (see [Uncoupled Heat Transfer Analysis](simaanl-c-heattransfer.md)) to compute a temperature field and then import the temperatures into a subsequent stress-displacement analysis (see [Static Stress Analysis](simaanl-c-static.md)).  You can import external fields for the following time-based analysis procedures:   * [Static Stress Analysis](simaanl-c-static.md) * [Implicit Dynamic Analysis Using Direct Integration](simaanl-c-dynamic.md) * [Explicit Dynamic Analysis](simaanl-c-expdynamic.md) * [Uncoupled Heat Transfer Analysis](simaanl-c-heattransfer.md) * [Fully Coupled Thermal-Stress Analysis](simaanl-c-couptempdisp.md) * [Piezoelectric Analysis](simaanl-c-piezoelectric.md) * [Coupled Thermal-Electrical Analysis](simaanl-c-jouleheating.md) * [Eddy Current Analysis](simaanl-c-eddycurrent.md) * [Coupled Pore Fluid Diffusion and Stress Analysis](simaanl-c-coupdiffstress.md) * [Mass Diffusion Analysis](simaanl-c-massdiffusion.md) * [Linear Elastic Fatigue Crack Growth Analysis](simaanl-c-fatiguecrackgrowth.md)   External fields can be imported only in one analysis step per analysis. The analysis step must be a general analysis (nonperturbation) step. For any subsequent analysis steps, the applied external fields remain constant based on the last imported values.  Input File Usage  Use the following options to import an external field to define a load, boundary condition, or predefined field:   ``` [FIELD IMPORT](.._SIMACAEKEYRefMap_simakey-r-fieldimport.md#simakey-r-fieldimport) [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name ```  Saving Fields in a Previous Analysis If the previous analysis is an Abaqus analysis, you request the source fields to write to the output database (.sim) file. When importing external fields over a time range, you must request output at a frequency to achieve sufficient solution accuracy (see [Controlling the Frequency of Output to the Output Database](.._SIMACAEOUTRefMap_simaout-c-dboutput-frequency.md)).  Identifying the Target and Source Fields When importing an external field, you define the target and source fields. The target field is the field defined in the current analysis. The source field is the field computed in a previous analysis. A field is a physical quantity that spans a region. The field is a node-based field if evaluated at nodes or an element-based field if evaluated at element centroids, integration points, or surface facets. You define a region by specifying a node set, an element set, or a surface regardless of where the field is evaluated.  When a node-based field is imported and an element set from the previous model is specified, the field is extracted from nodes of the elements in the specified element set. Similarly, when a node-based field is imported and a surface from the previous model is specified, the field is extracted from the nodes belonging to the surface facets of the specified surface. When an element-based field is imported and a node set from the previous model is specified, the element field is extracted from elements containing the nodes in the node set. Elements connected to nodes that are not in the node set are not included.  When importing an external field, you specify the region name space, the region name, and the physics quantity for the target field and the source field. The region name space specifies whether the region is a node set, an element set, or a surface. The region name is the name of a node set, element set, or surface.  When specifying the target field and source field parameters, you should consider the following conditions:   * The source field region name is optional. If it is not specified, the entire   model is used. However, you are encouraged to provide the source field region   name to reduce the computational cost associated with mapping and data transfer.   Abaqus has complex naming conventions, especially for assembly definitions. The   source file name must correspond to the name written to the   SIM results file when reading from a previous   Abaqus analysis. * When defining initial conditions, the target field region name space and physics   quantities are defined by the initial condition definition and, consequently,   are not used. * When defining distributions, the target field region name space, region name,   and physics quantities are defined by the distribution definition and,   consequently, are not used. * When used for node-based submodeling, the target region is a node set.   The physics quantities for the target field and the source field are defined using identifiers. The physics quantity identifiers for the target field depend on the analysis procedure and are the same identifiers used for co-simulation for imported fields. [Table 1](#simaanl-c-genlcapabilityimportprev-id-source-target__simaanl-c-genlcapabilityimportprev-table-id-keys) lists the supported identifiers, and detailed information is provided in [Identifying the Fields Exchanged across a Co-Simulation Interface](simaanl-c-cosimulationprep.md#simaanl-c-cosimulationprep-fields)). Most field-type quantities can be extracted from the output database file. If the source analysis is an Abaqus analysis, the identifiers are defined in [Abaqus/Standard output variable identifiers](.._SIMACAEOUTRefMap_simaout-c-stdoutputvar.md) and [Abaqus/Explicit Output Variable Identifiers](.._SIMACAEOUTRefMap_simaout-c-expoutputvar.md). Certain output variables are inconsistent between Abaqus solvers. For example, Abaqus/Standard uses the variable NT and Abaqus/Explicit uses the variable NT11 to output nodal temperatures. You should visualize the results database to obtain the appropriate field name.   Table 1. Input File Usage  Use the following options to import external fields to define history-dependent fields:   ``` [FIELD IMPORT](.._SIMACAEKEYRefMap_simakey-r-fieldimport.md#simakey-r-fieldimport) [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name NODES or ELEMENTS or SURFACE, target region, target quantity ID, NODES or ELEMENTS or SURFACE, source region, source quantity ID ```   For example,   ``` [FIELD IMPORT](.._SIMACAEKEYRefMap_simakey-r-fieldimport.md#simakey-r-fieldimport) [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=thermalAnalysis.sim, START TIME=0, END TIME=3600 ELEMENTS, ESTRESS, NT, ELEMENTS, ETHERMAL, NT ```   imports temperatures defined as nodal temperatures (NT) from output database thermalAnalysis.sim and applies them as a nodal temperature field in the current stress analysis. In this case the current analysis does not have temperature degrees of freedom; therefore, temperatures are imported as a predefined temperature field at the nodes. The temperatures are extracted from the body defined by element set ETHERMAL in the thermalAnalysis job and are mapped to the body defined by element set ESTRESS in the current analysis.  Importing Field Variables and Temperature as a Field Variable When importing field variables and temperature as a field variable, you might notice differences when you compare the source and target fields. There are two possible causes of these differences:  * Field variables and temperature as a field variable are mapped accurately and   imported at nodes. However, when saved to the output database, these quantities   are interpolated to element integration points. When contouring, some averaging   can occur depending on the contouring parameters selected. * For fully integrated first-order elements, a selective reduced-integration   technique is employed (see [Solid isoparametric quadrilaterals and hexahedra](.._SIMACAETHERefMap_simathe-c-solidisoquadhex.md)). In this case field variables and temperature as   a field variable are averaged at the element center and saved to the output   database.  The values correctly reflect the internal magnitudes used by Abaqus.  Importing Fields at a Specified Step and Increment If you are reading from a SIM database to define distributions or initial conditions, you can specify the step and the increment from which to extract the field values. You must ensure that the field is saved to the SIM database at the specified step and increment. If the increment is omitted, the values at the end of the step are imported.  Input File Usage  Use the following option to import field values at a specified step and increment of a previous analysis to define distribution or initial conditions:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), STEP=analysis step, INC=increment ```   Use the following option to import field values at the end of a specified step to define distribution or initial conditions:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), STEP=analysis step ```  Importing Fields at a Snap-Shot Point You can import fields at a specified snap-shot point. For a time-domain analysis, a snap-shot point is a specified time. For a frequency-domain analysis, a snap-shot point is a specified frequency or mode number. Frequency-domain results can be imported only from a non-SIM database. If the snap-shot point does not coincide with when the fields were saved, Abaqus linearly interpolates the field values between the snap-shot points available to obtain the field values at the request time or frequency.  You can specify the analysis step. In this case the time refers to the step time to extract field values in the output database, Otherwise, time refers to the total time.  To import the last saved values of an analysis step or of the analysis, do not specify any of the time or frequency parameters. This might be useful when reading from a linear perturbation step or from a steady-state analysis where time has no physical meaning.  Input File Usage  Use the following option to import fields at a specified time (specified as total time):   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), TYPE=SNAP SHOT, FILE=file name, TIME=total time ```   Use the following option to import fields at a specified analysis step and time (specified as step time):   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield),  TYPE=SNAP SHOT, STEP=analysis step, TIME=step time ```   Use the following option to import fields at the end of an analysis step:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield),  TYPE=SNAP SHOT, STEP=analysis step ```   Use the following option to import fields at the end of an analysis:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield),  TYPE=SNAP SHOT ```   Use the following option to import fields at a specified frequency:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield),  TYPE=SNAP SHOT, FREQ=frequency ```   Use the following option to import fields from a specified mode:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield)TYPE=SNAP SHOT, MODE=mode number ```  Importing Fields over a Specified Time Range You can import fields over a specified time range when importing fields to define history-dependent fields. You specify the start time and end time to define the time range in the upstream analysis to import fields.  Typically, data corresponding to the time points (increments of the downstream analysis) are not present in the output database. In this case field values are linearly interpolated between the time points stored in the output database to obtain values at the required time. Because the interpolation is linear, you must ensure that sufficient data is available in the output database to achieve sufficient accuracy.  If you are reading from a SIM database, you can specify the analysis step. In this case the time range refers to the step time to extract field values in the output database. Otherwise, time refers to the total time.  To import results over an analysis step or the entire analysis, do not specify a start and end time. If you omit the end time, results are imported as follows:  * If you specified an analysis step, results are imported to the end of the   analysis step. * If you omitted the analysis step, results are imported to the end of the   analysis.  Input File Usage  Use the following option to import fields over a specified time range (specified as total time):   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name, TYPE=TIME RANGE, START TIME=start time, END TIME=end time ```   Use the following option to import fields over a specified time range (specified as step time) in an analysis step:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name,  TYPE=TIME RANGE, STEP=analysis step, START TIME=start time,  END TIME=step end time ```   Use the following option to import fields over the entire upstream analysis:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name,  TYPE=TIME RANGE ```   Use the following option to import fields over a time range, starting at a specified time to the end of the analysis:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name, TYPE=TIME RANGE, START TIME=start time ```   Use the following option to import fields over a time range in a particular analysis step, starting at a specified time to the end of the analysis step:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name,  TYPE=TIME RANGE, STEP=analysis step, START TIME=start time, END TIME=step end time ```  Resolving Different Physics Time Scales When importing fields over a time range, Abaqus performs no time scaling by default. Specifically, if the upstream analysis time range is larger than the downstream analysis time range, Abaqus imports only the partial upstream fields. When the upstream analysis is shorter than the downstream analysis, Abaqus keeps the last imported field values constant for the remaining duration of the downstream analysis step.  For certain multiphysics simulations, the physics time scales might be different when performing a sequential analysis. For example, you can perform an electromagnetic analysis followed by a thermal-stress analysis importing heat losses. The time scale for the electromagnetic analysis might be significantly shorter than the time scale for conduction in the thermal-stress analysis. When the requested time range of the upstream analysis is different from the analysis step time of the downstream analysis, you can scale time such that the requested upstream analysis range is mapped over the entire downstream analysis step. In this case you must provide an end time value explicitly.  Input File Usage  Use the following option to map the upstream analysis results over the downstream analysis step:   ``` [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name, TYPE=TIME RANGE, TIME SCALING=ON, START TIME=start time, END TIME=end time ```  Translation Between Different Units Systems By default, Abaqus assumes consistent units between the Abaqus model and the previous analysis model; therefore, no units translation is necessary. If the Reader process supports units system and you have declared the units system in the Abaqus model (see [Units](.._SIMACAEMODRefMap_simamod-c-conventions.md#simamod-c-conventions-t-Units-sma-topic8)), the appropriate translation for mesh coordinates and field data is performed when field data are imported. This translation can be performed only for field types that have a predefined dimensionality (for example, the velocity field has a predefined dimensionality of LT{-1}). Field variables in Abaqus do not have a predefined dimensionality; therefore, unit translation for field variables is not performed. In this case you can scale the field variable by applying a field operation.  Applying Field Mapper Controls Typically, the source and target regions have different meshes. Fields are mapped conservatively between the source and target meshes, and Abaqus selects the most appropriate mapping algorithm based on the field properties. For most cases, the default settings for the mapping algorithm are adequate, but you can modify the mapper settings by specifying field mapper controls when importing distributions and initial conditions.  Missing members might be reported during the mapping operation. Missing members are nodes or elements for which the mapper cannot find a correspondence between source and target meshes. Consequently, the mapper does not compute field values at these locations. In this case, you can modify the default search tolerances or specify how to treat missing members. A zero value is applied automatically for missing members when importing history-dependent flux quantities (that is, forces, pressure, tractions, and heat fluxes) and no treatment is required.  Input File Usage  Use the following options to specify field mapper controls:   ``` [FIELD MAPPER CONTROLS](.._SIMACAEKEYRefMap_simakey-r-fieldmappercontrols.md#simakey-r-fieldmappercontrols), NAME=field mapper controls name [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name  , , , , , , field mapper controls name ```  Applying Field Operations You can apply one or more field operations when importing fields.  You can scale a field by a constant value by providing a scale factor. The scaling factor is intended to scale a field by a physical constant. It is not intended for unit conversion; for example, where you might need additional parameters to convert a temperature field.  You can extract a component of a vector or tensor field by providing a component index, i. The ith component of the source vector or tensor field is extracted and then mapped and imported as a scalar field. The components are extracted in the local coordinate system of the source field. You can apply component extraction when importing distributions, initial conditions, and history-dependent fields; it cannot be used for a submodel analysis.  If a region in the previous analysis is not colocated with the region in the current analysis, you must specify the translation and rotation to reposition the source region before field values are imported. You specify a rotation by giving two points, a and b, to define a rotation axis and a right-handed angular rotation about the axis. Local coordinate systems defined within the source region are translated and rotated according to the specified positioning data.  Input File Usage  Use the following options to scale a field by a constant value:   ``` [FIELD OPERATIONS](.._SIMACAEKEYRefMap_simakey-r-fieldoperations.md#simakey-r-fieldoperations), NAME=name, SCALE FACTOR=scale factor [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name  , , , , , , , field operation name ```   Use the following options to extract the ith component of the source field:   ``` [FIELD OPERATIONS](.._SIMACAEKEYRefMap_simakey-r-fieldoperations.md#simakey-r-fieldoperations), NAME=name, COMPONENT=index [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name  , , , , , , , field operation name ```   Use the following options to reposition the source region with the target region before importing data:   ``` [FIELD OPERATIONS](.._SIMACAEKEYRefMap_simakey-r-fieldoperations.md#simakey-r-fieldoperations), NAME=field operation name x, y, z x1, y1, z1, x2, y2, z2, rotation [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield), FILE=file name  , , , , , , , field operation name ```  Limitations The following limitations apply:  * Volumes or surfaces defined over beam, pipe, and truss elements or edges of   shell or membrane elements cannot be used to specify the target region. When   appropriate, you should import values at nodes. * Source or target regions with the following underlying element types are not   supported: modified triangular elements, modified tetrahedral elements,   second-order temperature-displacement elements, generalized plane strain   elements, and axisymmetric shells. * Tensor fields cannot be imported from a source region with two-dimensional   elements. * The use of nonunique nodal values (for example, temperature and field variables) on shell   elements from an Abaqus-generated SIM file using field import is not   supported. * Reading fields from non-SIM databases is   supported only when importing history-dependent fields; it is not supported when   importing distributions and initial conditions. * When importing fields from the same results database using multiple [EXTERNAL FIELD](.._SIMACAEKEYRefMap_simakey-r-externalfield.md#simakey-r-externalfield) options,   you must import all fields at a specific time or over a time range; in either   case, the time or the time range must be the same.  Because importing external fields in a sequential analysis is a general capability, no error message is issued if Abaqus encounters the conditions listed above. |
