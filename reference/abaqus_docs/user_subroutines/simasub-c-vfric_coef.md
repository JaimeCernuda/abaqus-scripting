C       return       end ```  Variables to Be Defined fCoef(nBlock,2)  fCoef(1,1) and other entries of the first column of the fCoef array should be updated to current values of the friction coefficient for all contacting points. fCoef(1,2) and other entries of the second column of the fCoef array should not be updated for Abaqus/Explicit analyses. You can model anisotropic friction with directional preference specified as a surface property (see [Anisotropic Friction with Directional Preference as a Surface Property](.._SIMACAEITNRefMap_simaitn-c-friction.md#simaitn-c-friction-anisotropic-surfprop) and a nominal friction coefficient specified in fCoef(1,1) and other entries of the first column of the fCoef array.  fCoefDeriv(nBlock,20,2)  This array is not applicable to Abaqus/Explicit analyses.  Variables That Can Be Updated rData(i\_rfc\_StateV)  The array of real values starting from this offset corresponds to the solution-dependent state variables. You specify the number of available state variables ([Allocating Space for Solution-Dependent State Variables](simasub-c-subroutineover.md#simaanl-c-usubrout-allocatespace)). These state variables are passed in with values at the start of the increment. Update them to their corresponding values at the end of the increment. See the user subroutine interface provided earlier for an example of how to access the array of state variables from the buffer rData.  Variables Passed in for Information nBlock  Number of contacting points to be processed in this call to [VFRIC\_COEF](simasub-c-vfric_coef.md#simasub-c-vfric_coef).  nProps  User-specified number of property values associated with this friction model.  nTemp  1 if the temperature is defined, and 0 if the temperature is not defined.  nFields  Number of user-specified field variables.  iData(i\_ifc\_KStep)  Step number.  iData(i\_ifc\_KInc)  Increment number.  iData(i\_ifc\_Kit)  Not applicable to Abaqus/Explicit analyses.  iData(i\_ifc\_Node)  Equal to 0 in Abaqus/Explicit analyses. The secondary node number varies among the contact constraints processed in a single call to this user subroutine.  iData(i\_ifc\_nStateV)  The number of state variables you have specified. The default value is 0.  iData(i\_ifc\_nFDir)  Equal to 1 in Abaqus/Explicit analyses. You are expected to provide a single friction coefficient for each contact constraint in the user subroutine.  rData(i\_rfc\_TimStep)  Value of step time.  rData(i\_rfc\_TimGlb)  Value of total time.  rData(i\_rfc\_DTimCur)  Current time increment size.  rData(i\_rfc\_Drot)  The list of four value entries starting from this offset corresponds to the column major storage of the 2 × 2 rotation increment matrix. For Abaqus/Explicit, this rotation increment matrix is always provided as the identity matrix.  surfInt  User-specified surface interaction name, left justified.  surfSec  Not applicable to Abaqus/Explicit analyses.  surfMain  Not applicable to Abaqus/Explicit analyses.  props(nProps)  User-specified vector of property values to define the frictional coefficient at contacting points.  slipData(nBlock,6)  The entries slipData(kBlock,i\_SD\_SlipRateMag) and slipData(kBlock,i\_SD\_SlipEq) contain the slip rate magnitude and total accumulated slip distance for a contacting point indexed by kBlock for the current time increment. Other entries of slipData are not applicable to Abaqus/Explicit analyses.  pressure(nBlock)  Array containing the pressure at the contact point projected at the end of the current time increment.  tempAvg(nBlock)  Average current temperature between the main and secondary surfaces at the contacting points.  fieldAvg(nBlock,nFields)  Average current value of all the user-specified field variables between the main and secondary surfaces at the contacting points. |
