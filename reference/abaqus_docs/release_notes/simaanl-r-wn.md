State Space Solver for Transient Modal Dynamic Analysis You can use the new state space solver to perform transient modal dynamic analysis for models with nondiagonal modal damping operators.  Benefits: The new solver is unconditionally stable and offers improved performance for models with many time increments and a moderate number of modes. It also supports coupled structural-acoustic analysis.  In earlier releases, the only solver available for transient modal dynamic analysis with nondiagonal modal damping was the conventional solver. The conventional solver uses a time integration scheme based on the assumption that the nondiagonal entries of the modal damping operator vary linearly within each time increment together with the loads. It calculates the approximate modal solution, and the solution accuracy depends on the time step size. In addition, the time integration algorithm is not unconditionally stable, particularly for models with a high level of damping. For common engineering simulations, the accuracy and stability of the conventional solver is usually acceptable. However, obtaining an accurate and stable solution using the conventional solver requires the use of very small time increments for specific cases. In addition, the conventional solver does not support coupled structural-acoustic analysis.  The new state space transient modal dynamic solver calculates the exact modal solution for systems with arbitrary modal damping for loads that vary piecewise linearly with time. This solver uses the complex eigenmodes of the unsymmetric modal state space operator to represent the real transient modal solution. The solution includes two phases: solving the unsymmetric eigenvalue problem for the state space operator at the “setup” phase and calculating the transient solution at the “apply” phase. The setup phase is the most computationally intensive part of the analysis. It can be costly for systems with many thousands of modes. However, the calculated solution with the state space solver is more accurate than for the conventional solver and the algorithm is unconditionally stable. In addition, the state space solver supports structural-acoustic transient modal analysis using the modal subspace built from the coupled structural-acoustic eigenmodes or from the uncoupled structural and acoustic eigenmodes.  Related topics:  [Transient Modal Dynamic Analysis](.._SIMACAEANLRefMap_simaanl-c-modaldynamic.md).  Unit System Translation The SIMULIA Co-Simulation Engine now supports unit system translation.  Benefits: You now have the flexibility to use the unit system best suited to your industrial workflow.  To avoid mistakes, it is best to perform coupled multiphysics and multiscale simulation where both models use the same units. Abaqus has no units built into it and assumes self-consistent units. Some third-party solvers might represent their internal data in a unit system different from the one in which the user defined the model.  The SIMULIA Co-Simulation Engine typically tabs into the solver and consequently exchanges field data in the solver’s unit system. This forces the Abaqus model to be in the unit system used by the other solver’s internal format and can lead to unconventional model specification. For example, consider a sequential analysis of a circuit board modeled in CST Studio Suite with results imported into Abaqus. You might employ the CGS system (centimeter-gram-seconds) to define the electromagnetic model. However, CST Studio Suite converts everything to SI (International System) units to perform calculations. This forces the Abaqus model to be in SI units and to use meters as the length dimension for model definition (geometry, material data, load, etc.), which is an unconventional choice for this particular workflow.  Translation between unit systems is available only if the following are true:  * the unit system is defined in the Abaqus model and * the other solver supports unit system translation through the co-simulation   service.  Related topics:  [Defining a Unit System for Translating Data with Other Solvers](.._SIMACAEMODRefMap_simamod-c-conventions.md#simamod-c-conventions-unitsystem) and [\*UNIT SYSTEM](.._SIMACAEKEYRefMap_simakey-r-unitsystem.md). Specifying Design Responses in an Adjoint Design Sensitivity Analysis You can now specify design responses in an adjoint design sensitivity analysis. In addition, you can prevent sensitivity calculations and output that might not be important for design optimization.  Benefits: You can manage the specification of design responses more effectively and prevent the output database from becoming too large.  The list of available operators for node and element design responses now includes the maximum absolute and the minimum absolute operators. These operators can be helpful in situations such as the following:  * In the context of node responses, the maximum absolute operator is useful when the   nodal displacements for a node set that contains many nodes should be constrained to   be less than a certain value. Without the maximum absolute operator, you must define   one node response for each node in the node set, leading to many node responses (and   corresponding adjoint sensitivities) in the output database. When you use the   maximum absolute operator, you need to define only a single design response that   uses this design objective or constraint. * The minimum absolute operator is useful when the reaction force for a node set   that contains many nodes must be larger than a certain value. Without the minimum   absolute operator, you must define one node response for each node in the node set,   leading to many node responses (and corresponding adjoint sensitivities) in the   output database. When you use the minimum absolute operator, you need to define only   a single design response that uses this design objective or constraint. * You can now specify lower and upper bounds on the values of a design response   outside of which Abaqus will not compute the adjoint sensitivities. By default, Abaqus writes the design response and the corresponding adjoint sensitivities to the   output database for all design responses that do not have any prescribed bounds for   the design response definition. In some situations, the sensitivities are necessary   only if the value of a design response is within a certain range. In these cases,   specifying the lower and upper bounds on the design response values provides a   convenient way to limit the sensitivity calculations and the size of the output   database. Undrained Pore Fluid Flow and Stress Analysis You can now perform an undrained pore fluid flow and stress analysis in Abaqus/Explicit.  Benefits: You can account for the presence of a permeating pore fluid and its effect on the mechanical response of a saturated granular solid skeleton under dynamic loading conditions.  A porous medium typically consists of a solid skeleton of numerous solid grains that are “loosely packed” and a permeating pore fluid that occupies a system of interconnected pores among these solid grains. You can ignore the effect of fluid flow in situations when the loading rate is significantly faster than the rate at which pore fluid can drain from the porous medium. This corresponds to the undrained conditions.  The undrained pore fluid flow and stress analysis functionality in Abaqus/Explicit is intended for the simulation of fully saturated porous media under undrained conditions. The functionality enables modeling the increase in stiffness of the soil in applications such as trenching, gouging, and pile driving. In these applications, you can ignore fluid diffusion terms when the rate of loading is fast compared to the characteristic time of the diffusion process. Benefits: The iterative solver is now able to converge on models on which it could not converge in earlier releases (for example, automotive battery structural simulations) or on models for which convergence was prohibitively slow (for example, electric engine analyses).  The new domain decomposition algorithm takes into account the connectivity of the finite element model, the element formulation details, and the material properties. It creates a better clustering of elements with similar properties and separates out clusters with dissimilar properties. This makes it easier for the iterative solver to find a smooth solution in individual aggregates, which results in improved convergence rates overall. The algorithm optimizes the load balance between domains for large models in parallel runs by accounting for the actual computational costs of different elements. The solution time reduction due to the improved domain decomposition varies from model to model. The improvement can be moderate for some finite element models, but it can be significant for large-scale models with complicated geometry using higher-order element formulations. Generating Reduced Bases for Use with Nonlinear Flexible Multi-Body Systems A new analysis technique in Abaqus/Standard reads operator data from upstream analyses and generates reduced bases for use in downstream nonlinear flexible multi-body system (MBS) simulations with Simpack.  Benefits: This streamlines the process for preparing MBS simulations that capture large deformation effects with high accuracy and fast run times.  A reduced basis is a set of basis vectors that can represent solutions from preceding analysis cases when they are superimposed with according scaling factors. You can now generate reduced bases for use in downstream nonlinear flexible MBS simulations with Simpack as follows:  1. Define a nonlinear static analysis case that ramps up a large deformation of a    flexible component in a shape that is characteristic for its behavior in downstream    system simulations. For example, apply a distributed load that acts on the surface    of a wind turbine rotor blade in the flap-wise direction, or define a spring support    for a twist beam axle and apply a twisting load at the wheel attachment points. 2. Output the operator data at various deformation levels. 3. Add natural frequency extraction steps at various deformation levels. 4. Add the reduced basis generation step.  The reduced basis generation step computes the reduced basis from the solution data and computes the auxiliary operator data from all the preceding analysis steps. The reduced basis and projected operator data are written to a SIM (.sim) file. Optionally, you can write a Simpack Flexible Body Interface (.fbi) file with a complete Simpack nonlinear flexible body definition that you can assign directly to a nonlinear flexible body in Simpack. Benefits: Using the new solver can significantly reduce the analysis time for damped finite element models with general structural damping and specific viscous damping properties.  You can use the new spectral solver for the special cases of mode-based steady-state dynamic simulations. For all cases, you can apply any kind of structural damping in the model. The special cases are defined by the complementary viscous damping properties.  |  |  |  | | --- | --- | --- | | Case 1 | No viscous damping | No material, global, or modal viscous damping | | No dashpot elements, connector damping, or substructures with viscous damping | | No matrix input data for the viscous damping | | No other possible sources of the viscous damping | | Case 2 | Low rank viscous damping operator | Viscous damping is defined locally in the model, for example, using dashpot elements, connector damping, or substructures with viscous damping | | Structural-acoustic coupled steady-state dynamic analysis using uncoupled eigenmodes when the number of acoustic modes is significantly smaller than the number of the structural modes | | Modal viscous damping defined for selected modes |  You can use the spectral solver for mechanical, acoustic, and structural-acoustic analyses. Using the spectral solver can be beneficial for models with the mentioned special damping properties when many eigenmodes and many points in the frequency domain are used for the frequency response calculation.  The spectral solver algorithm consists of two analysis phases: the Setup Solver Phase and the Apply Solver Phase. The computational cost of the Setup Solver Phase depends on the number of the eigenmodes, and it can be significant when that number is high. The computational cost of the Apply Solver Phase is proportional to the number of the frequency points specified for the frequency response calculation, and the solution calculation at a frequency point is relatively cheap. Therefore, the spectral solver can be less effective for the analyses with a small number of frequency points (when the setup phase dominates), but it can be very effective for the same model when more frequency points are used. Formation of Tie Constraints in Import Analysis In an Abaqus/Explicit import analysis, Abaqus/Explicit now forms tie constraints using the original instead of the updated configuration if the definitions of both the main and secondary surfaces to be tied are unchanged from the original analysis.  Benefits: The new protocol makes it easier to establish initial equilibrium due to tie constraints in the imported model.  The new protocol prevents the formation of new tie constraints for nodes on the surfaces that were previously untied. Such new tie constraints, if formed, can adversely affect the consistency of the imported model. For example, if the previously untied nodes are in a state of contact, tying these nodes results in deletion of the contact state associated with the nodes. The new protocol also guarantees formation of the same tie constraints for the surfaces in the import analysis as in the original analysis. It is used regardless of whether you specify the original or the updated configuration as the reference configuration for import.
