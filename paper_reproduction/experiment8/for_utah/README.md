# Abaqus 2025 Topology Optimization — Working Pipeline

Tested on CHPC (University of Utah) with Abaqus 2025 (3DEXPERIENCE R2025x), Feb 19, 2026.

## The Problem

Two Abaqus Python API calls for topology optimization are **broken in noGUI mode** in Abaqus 2025:

- `OptimizationProcess.writeParAndInputFiles()` — throws `KeyError` (prototype job not found in internal C++ map)
- `OptimizationProcess.submit()` — segfaults (null pointer dereference in `cow_Virtual<ajbC_Job>::Copy`)

See the `broken/` subfolder for scripts, SLURM output, and crash dumps that reproduce these failures.

## The Working Hybrid Approach

The pipeline that **does work** is:

```
CAE Python API (noGUI)          Tosca CLI
──────────────────────          ─────────
1. Build geometry
2. Mesh (C3D8R)
3. Define material + section
4. Assembly, step, BCs, loads
5. writeInput() ──────────────> 6. Flatten .inp for Tosca
                                7. Generate .par file
                                8. tosca optimize -p file.par -s abaqus
                                9. Output: ISO_SMOOTHING.stl
```

## How to Reproduce

### Prerequisites
- Abaqus 2025 with Tosca license
- Linux (tested on RHEL 8, x86_64)

### Run the working pipeline
```bash
module load abaqus/2025
unset SLURM_GTIDS

cd /tmp/tosca_test
abaqus cae noGUI=exp8e_par_to_tosca.py
```

The script will:
1. Build a 100x40x20mm steel block (945 nodes, 640 elements)
2. Try `writeParAndInputFiles()` (will fail with KeyError)
3. Fall back to `writeInput()` + flatten .inp + generate .par
4. Run `tosca optimize` CLI
5. Produce `ISO_SMOOTHING.stl` in the Tosca output directory

### Run the broken API tests
```bash
# writeParAndInputFiles() — KeyError on all 4 variations
abaqus cae noGUI=broken/8c_writeParAndInputFiles/exp8c_write_par.py

# submit() — segfaults immediately
abaqus cae noGUI=broken/8d_submit/exp8d_submit.py
```

## Key Technical Details

### Flattening the .inp

Abaqus CAE writes hierarchical .inp files:
```
*Part, name=Block
  *Node
    1, 100., 40., 20.
    ...
  *Element
    ...
  *Elset, elset=AllCells, internal
    ...
*End Part
*Assembly, name=Assembly
  *Instance, name=Block-1, part=Block
  *End Instance
*End Assembly
```

Tosca requires flat .inp files (no Part/Instance/Assembly hierarchy). The flattening:
- **Removes** wrapper lines: `*Part`, `*End Part`, `*Instance`, `*End Instance`, `*Assembly`, `*End Assembly`
- **Keeps** all content inside (nodes, elements, sets, sections, etc.)
- **Strips** `instance=Block-1.` prefixes from set references
- **Removes** `internal` keyword from `*Elset`/`*Nset` definitions

### Tosca .par Format

The .par file uses Tosca's own syntax (not Abaqus .inp syntax):
- `FEM_INPUT` — points to the flattened .inp
- `DV_TOPO` — defines design variable group (which elements can change)
- `DVCON_TOPO` with `CHECK_TYPE = FROZEN` — freezes boundary elements
- `DRESP` — design responses (strain energy, volume)
- `OBJ_FUNC` — objective function (minimize strain energy)
- `CONSTRAINT` with `MAGNITUDE = REL` — volume constraint (relative, <= 0.5)
- `OPTIMIZE` with `DV =` and `STRATEGY = TOPO_SENSITIVITY`
- `OPT_PARAM` — filter radius
- `STOP` — max iterations
- `SMOOTH` — STL output with isosurface smoothing
